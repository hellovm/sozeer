## 1. 功能

### 功能域总览

| 模块 | 能力 |
|---|---|
| **写作内核** | 三级大纲 · 场景层 · 多阶段生成流水线（brief→context→generate→gate→polish→register）· 去 AI 腔 · 片段重拍（不动其他部分）· 批量续写 N 章 |
| **一致性引擎** | 跨章记忆 · 人物关系图谱 · 伏笔台账（自动登记/到期提醒）· 情绪曲线 · 信息差管理 · 七维质量闸门（字数/段落/禁用词/中英混排/AI 味/钩子/重复度） |
| **短剧工坊** | 分集/剧本/分镜/资产 · **角色自动提取 + 定妆图参考管线**（跨镜人物一致性）· 八段分镜提示词 · 多宫格分镜稿 · 图/视频/配音批量生成 · 剪映导出 |
| **管理后台** | 16 个页面（独立 `/admin`）· RBAC · 审计 · 风控 |
| **配置中心** | 50+ 配置项 · diff 先行 · 变更历史与回滚 · 高危操作留痕 |
| **队列与并发** | Redis 原子出队（Lua）· 并发闸门 · 断点续跑 · 降级兜底（Redis 挂→同步执行） |
| **可观测性** | 健康探针 · 成本台账 · 额度预警 · 数据洞察（采纳/纠错累计）· 匿名遥测（可关） |

**定位：单用户 / 小团队**。数据模型预留 `workspace_id`，但**不做多租户隔离**——明确边界比含糊支持更负责。

### 你原来的人工流程，在平台里的对应物

| 你原来的做法 | 平台里的对应物 |
|---|---|
| 创作总纲（人物/境界/分卷/写作准则） | 状态中枢（characters / world_settings / volumes / style_profiles） |
| 伏笔追踪表随写随更新 | 伏笔台账 + 写后自动登记（摘要/新埋/回收/人物状态） |
| 每章按起承转钩写 | `skills/packs/chapter_write.md`（可在线编辑） |
| 禁用词、段落长度、章末钩子 | 质量闸门（规则化，不靠模型自觉） |
| 各平台字数/规范自检 | 配置中心按平台切换参数 |
| 手动改稿 | Web 编辑器直接改 → Git 版本记录 → 一键回滚 |

### 一次「写下一章」内部发生了什么

```
brief    章前任务单（本章推进/埋/收/爽点/钩子）   ← planner 模型
context  上下文装配（风格DNA + 世界观 + 卷大纲 + 任务单
         + 人物卡 + 活跃伏笔(含到期提醒) + 摘要链 + 前 3 章全文）
generate 正文流式生成                              ← writer 模型
gate     质量闸门（字数/段落/禁用词/中英混排/AI味/钩子/重复度）
polish   定点改写（只改违规处，最多 1 轮）          ← writer 模型
───────── 以上产出草稿，等你在 WebUI 点「采纳」─────────
accept   落库 + Git commit
register 自动登记：摘要 / 新伏笔 / 回收标记 / 人物状态  ← critic 模型
```

每次执行都写进 `runs` 表：上下文快照、模型、成本、闸门分数、耗时 —— **可复现、可 A/B、可算账**。

**质量来自三件事，不是某个神仙 Prompt**：
1. 世界锚点稳定（写章前强制装配上下文）
2. 硬纪律（闸门校验 + 定点重写）
3. 增量登记（伏笔/人物状态随写随更新）

## 2. 核心技术

**技术栈**：FastAPI · SQLAlchemy · PostgreSQL（本地开发可 SQLite）· Redis ·
Vue 3 + Vite + TypeScript + Pinia · Docker

### 几个刻意的选择（不是"用了什么"，而是"为什么这么选"）

| 决策 | 原因 |
|---|---|
| **自研薄编排内核**（不用 LangChain 等） | 生成流程需要"锚点冻结 + 种子固定 + 边界校验"这类**强控制**，通用框架反而更难做 |
| **模型走云端 API**（不内置本地推理） | 让部署方自己选模型与成本档位；本项目不自带大模型。OpenAI 兼容协议，主流厂商均可接入 |
| **队列用 Redis**（非数据库轮询） | 需要原子出队（Lua）与并发闸门；DB 轮询做不到，且会成为瓶颈 |
| **规则引擎做质量判定，模型只做抽取** | 能确定性判定的不用模型 —— 又快又准，且**不会编造理由** |
| **前端重构而非渐进改造** | 旧版单文件 JS 已到维护极限；Vue3 双轨并行灰度后切换 |
| **章节即 Git 仓库** | 每本书一个 Git 仓库，章节即文件：版本、diff、回滚、备份全免费 |

## 5. 部署指引

### 5.1 本地跑起来（30 秒）

```bash
# 依赖
pip install -r requirements.txt

# 启动
python -m uvicorn apps.api.main:app --host 0.0.0.0 --port 8000
# 打开 http://localhost:8000
```

### 5.2 服务器部署（Docker，推荐生产）

```bash
docker compose up -d
```

仓库内含基础部署产物（`Dockerfile` / `docker-compose.yml`）。

### 5.3 首次使用流程

1. 点「**导入小说**」，填已有小说目录（需含 `大纲/00-创作总纲.md`、`大纲/伏笔追踪.md`、`正文/第XXX章.md`）
2. 进「**配置中心 → 模型**」添加一个云端模型（OpenAI 兼容协议），点「测试连通」
3. 即可开写：生成草稿 → 编辑器审改 → 采纳

### 5.4 配置中心能改什么

| 模块 | 说明 |
|---|---|
| 模型 | Provider / Base URL / Key（本地存储）/ 模型 ID / 单价 / 温度；**角色路由**：writer 正文、planner 大纲与任务单、critic 判定与摘要，可分别指向不同模型省钱 |
| 技能 | 5 个 SKILL.md 可在线编辑，改后覆盖磁盘版本，可一键恢复默认 |
| 风格纪律 | 视角、段落上限、禁用词表、写作准则、**范文锚定**（贴一段你满意的正文锁住语感） |
| 平台规范 | 字数上下限（番茄 2000–2200 已预置，其他平台改这里） |

### 5.5 匿名使用统计（遥测）

**默认开启，仅匿名聚合统计**（部署规模/功能使用计数，**绝不包含作品内容与任何个人
身份信息**，上报前红线校验，命中即整包丢弃）。可随时关闭，关闭不影响任何功能：

```bash
SOZEER_TELEMETRY=off ./start.sh        # 或 后台 → 设置 → 数据与隐私
```

完整收集清单：`GET /api/telemetry/disclosure`（无需登录）。

### 5.6 性能参考（实测）

| 场景 | 能力 |
|---|---|
| 并发用户 | **200 全绿**（2 核 / 3.7GB 内存单机实测） |
| 数据库连接 | 100（PostgreSQL `max_connections`） |
| 部署形态 | 单机部署推荐 |
